## 已确认决定的具体边界

### D4：文档支持范围

状态：2026-09-27 用户确认 PDF、Word、TXT、Excel，并确认扫描版 PDF 纳入首期。

计划按常见扩展名覆盖 `.pdf`、`.docx`/`.doc`、`.txt`、`.xlsx`/`.xls`。M0 分别验证解析和定位：旧 `.doc` 如需受限转换，须保留原始文件、转换器版本和来源定位；不能只支持 `.docx` 后笼统宣称已支持全部 Word 范围。宏文档、嵌入程序与任意其他后缀不因文件类别名称自动获得执行能力。

- 文字型 PDF 读取已有文本层；扫描版 PDF 通过 OCR 识别文字。
- 同一文件混合文字页与扫描页时逐页处理，避免遗漏扫描页或重复索引已有文本。
- OCR 引用保留原始页码、页面区域、识别文本和处理版本；识别不清时明确说明，不补造字符、数值或单位。

扫描文字识别与理解科研图表是不同能力，不能因支持扫描文字就宣称能够解读全部图片、公式或复杂表格。各格式中未读取的内容必须标记覆盖缺口。

Excel 复用现有 FileObject、SourceDocument 索引和 sheet/cell/range 定位。原文检索可读取尚未确认区域中的有界内容，并明确标注为“文件原文，未确认实验含义”；正式实验身份、字段含义、单位解释和计算输入仍来自已确认区域/已接受快照。不要把 Excel 扁平化成丢失坐标的纯文本，也不要另建一套 Excel 上传/数据发布链路。

决定影响 M0 解析选型、M1 索引与来源定位、M4 原文查看器、M5 语料和费用。PDF 图表中的数值不能默认为可用实验数据。

### D5：资料读取完成后直接用于问答（已确认）

状态：2026-09-27 用户确认可以直接使用。

PDF、Word、TXT 和 Excel 上传并完成相应解析/索引后，即可在已读取范围内检索和引用，无需额外“确认使用”步骤。尚在解析或部分不可读的内容保持明确状态，不能假装已经读完。

问答区分“资料原文”“项目背景记录”“已确认区域含义”“已接受实验值”。Excel 中尚未确认的值只能作为准确单元格的文件内容引用；不能自动映射成某个实验结果、补造单位或越过科学计算/发布审核。写入项目背景同样不是自动纳入问答的副作用。

M0 应同步 AI 上下文与科学契约，明确本期新增的只读原文证据类型，同时保留已接受数据的分析/发布不变量；不把当前契约中的 accepted-evidence 约束整体删除。

### D6：View 成员可以发起只读问答（已确认）

状态：2026-09-27 用户确认。

具备项目 View/read 的成员可以发起纯只读问答；上传、分析执行、确认及发布权限不变。

现有 `AnalysisService.createAgentRun` 使用 `propose`，因此这是实际权限扩展，需要单独的只读入口/操作判断，不能仅把现有混合入口整体改为 `read`。问答所需的服务端运行记录与答案保存属于该只读问答操作的受限副作用，不授予通用项目修改权限。

公开 Guest 继续禁止 AI。只有 selected-experiments 权限的成员，不能因为问答而取得全项目文档/实验访问；本期可沿用 full-project 入口限制，不能扩大范围。保存回答与打开引用时同样重新校验权限。

## 实施时由 Astra 解决的工程选择

以下保留实施前的选择依据。工程选择现已完成：实际解析器、版本、词法检索、七个只读工具、持久化和资源限额见[实现契约](../contracts/research-qa-v1.md)，样例结果见[验证报告](../qa/research-qa-verification.md)。未引入新的外部 OCR 或 embedding 服务。今后除非触发新的产品范围、外部服务或权限变更，无需逐项请用户批准。

| 问题 | 选择依据与边界 |
| --- | --- |
| 解析库和版本 | 使用 PDF、DOC/DOCX、TXT、XLS/XLSX 代表性文件验证页码/段落/表格/单元格定位、编码、资源上限和部署兼容性；不要仅凭库名选择 |
| OCR 引擎与配置 | 用中英文清晰扫描、混合页、旋转/倾斜、多栏及低清晰度样例验证识别和回源；保存引擎/语言/配置版本，限制页级时间、内存及并发；优先在现有部署边界内处理 |
| 检索策略 | 先测术语、编号、中文问题/英文论文和跨段落问题；允许词法检索、章节上下文及既有 provider 的受限重排；向量或新 embedding 服务不是预设依赖 |
| 工具粒度 | 保留搜索→精读、查找身份→读取精确值；内部可组合；不得用通用数据库/执行器入口扩大权限 |
| 编排实现 | 复用选定基线中已可用的运行机制和 provider 网关；隔离稳定性分支不自动成为依赖；不为本期复制第二套队列或审核状态 |
| 数据表/API 名称 | 按当前 v1 契约、版本化迁移和生成客户端规范确定；工具名不是 HTTP API 的一一映射 |
| 限额与性能 | 在 M0 冻结文件大小/页数、片段长度、分页、工具轮次、provider 请求/令牌上限及总期限；记录测试硬件和延迟分布，不承诺未测 SLA |
| 文档状态 | 有界解析、重试、归档和旧引用保留按工具设计；物理清除与跨项目资料库不在本期默认范围 |
| 开发基线 | 检查当前工作区与可复用 checkout；保留既有修改；协调旧文档与 v1 实现差异，避免恢复退休链路 |

OCR 已在已确认范围内，选型不再需要重复询问是否支持扫描件。增加新的外部数据服务、跨租户/项目共享、超出 D6 的权限扩展、放宽计算审核或新增科研图像/曲线的视觉分析，需要先讨论范围变更。
